## 本節的位置

1-3 到 1-6 攻擊的是機器——密碼、封包、連線資源。這節攻擊的是**使用者相信眼前畫面的那個瞬間**。整節回答：**當使用者照著「安全守則」做，攻擊者怎麼一層層繞過？最後剩下什麼可以信？**
① 基本型 → ② 連網址都騙（ファーミング）→ ③ 連點連結都不用（ドライブバイ、SEO）→ ④ 你看到的不是你點到的（クリックジャッキング）→ ⑤ 嚇你付錢與偷偷偵察（ワンクリック、Web ビーコン）→ ⑥ 誰該做什麼對策。

---

## ① 基本型：フィッシング與它的變體

フィッシング（phishing）＝偽裝成知名企業或金融機構寄信，誘導使用者到**假網站**輸入個資、卡號、帳密。**入口是使用者自己點了連結。**

同一套騙術換管道：

| 名稱 | 管道 | 例子 |
|---|---|---|
| フィッシング | 郵件 | 「您的帳戶異常，請點此確認」 |
| **スミッシング（smishing＝SMS＋phishing）** | 簡訊 | 「包裹無法投遞，請更新地址」 |
| **ビッシング（vishing＝voice phishing）** | 電話語音 | 冒充銀行客服來電 |

> 對應的守則是「**不要點信裡的連結、確認網址是不是真的**」。②③④就是攻擊者怎麼繞過這兩條。

---

## ② 網址是真的、網站是假的：ファーミング

フィッシング要騙你**點假連結**；ファーミング（pharming）讓你**輸入正確網址也會到假網站**。它竄改的是名前解決（なまえかいけつ，網址→IP 的對應）：

| 做法 | 改了哪裡 |
|---|---|
| 竄改使用者電腦裡的 **hosts ファイル** | 本機的名稱對應表 |
| 攻擊 **DNS サーバ**塞入假對應 | **DNS キャッシュポイズニング**（DNS cache poisoning，機制在 1-10） |

> **最高頻考點**：網址列顯示的是**真的網址**，所以「**確認 URL（Uniform Resource Locator）是否正確**」對ファーミング**無效**。
> 有效的是**確認サーバ証明書（server certificate）**——假網站拿不出正牌憑證。題目很愛拿這組對照考人。

名字由來：phishing 是「釣」，一隻一隻上鉤；pharming 是「養殖（farming）」，把整片流量導過來。

---

## ③ 連點都不用點：ドライブバイダウンロード與 SEO ポイズニング

「不要開可疑郵件、不要點信裡的連結」這條防線，被兩種攻擊繞過：

| 攻擊 | 做法 | 繞過的點 |
|---|---|---|
| **ドライブバイダウンロード（drive-by download）** | 只是瀏覽被竄改的網站就中招，利用**瀏覽器或 OS 的脆弱性**（→ 1-2） | 你什麼都沒點，正常網站被改了 |
| **SEO ポイズニング（Search Engine Optimization poisoning）** | **操弄搜尋排名，讓惡意網站出現在搜尋結果前段** | 你自己搜尋、自己判斷、自己點 |

> **陷阱**：SEO ポイズニング**不是「讓 SEO 變差」，方向相反**——是把惡意網站的 SEO 做得很好。

---

## ④ 你看到的不是你點到的：クリックジャッキング

クリックジャッキング（clickjacking）用**透明的圖層／iframe（inline frame）**疊在正規網站上，使用者以為點的是 A，實際點到 B。結果可能在不知情下洩漏個資或註冊了某服務。

> 例：畫面上是「播放影片」按鈕，底下透明疊著另一個網站的「同意公開個人資料」按鈕。

對策在**網站營運者**：用 **X-Frame-Options** 或 **CSP（Content Security Policy）frame-ancestors** 宣告「本站不得被 iframe 嵌入」。

## ⑤ 嚇你付錢與偷偷偵察：ワンクリック詐欺、Web ビーコン

### ワンクリック詐欺（one-click fraud）

點一下按鈕就顯示「入会（にゅうかい）完成，請支付會費◯◯元」，常見於交友、成人網站，並秀出你的 **IP 位址、OS、瀏覽器版本**。

**那些資訊任何網站都拿得到，認不出你本人**——秀出來只是營造「我已掌握你個資」的錯覺，逼你付錢。

> **對策：無視、不付款、絕對不主動聯絡對方**（一聯絡就等於親手交出真正的個資）。
> 相關詞：**ツークリック詐欺（two-click fraud）**——多加一次確認點擊，偽裝成「你已同意」以規避法律責任。

### Web ビーコン（web beacon）

嵌在網頁或 HTML 郵件中的 **1×1 像素透明圖片**。圖片本身沒意義，重點是**瀏覽器去抓這張圖的動作**會把資訊送到對方伺服器：

| 送出的資訊 | 內容 |
|---|---|
| IP 位址 | 從哪裡連 |
| User-Agent | OS／瀏覽器版本 |
| 存取時間 | 何時開 |
| クッキー（cookie） | 辨識同一人 |
| **リファラ（referer）** | **前一頁的 URL**（從哪一頁連過來的） |

**在 HTML 郵件裡的用途是開封確認（かいふうかくにん）**——寄件者能知道你**有沒有開、何時開、從哪開**。對垃圾信業者而言，你一開信就等於宣告「**這個地址是活的**」，之後垃圾信只會更多。

> **標準考點**：所以郵件軟體預設**關閉画像の自動表示（がぞうのじどうひょうじ）**。

## ⑥ 對策：依「誰該做」分開記

題目常拆成使用者與營運者兩種問法：

| 立場 | 對策 | 對付 |
|---|---|---|
| **使用者** | 不點郵件／簡訊裡的連結，改用書籤或手動輸入網址 | フィッシング、スミッシング |
| 使用者 | **確認サーバ証明書** | **ファーミング（唯一有效的確認方式）** |
| 使用者 | 對突然跳出的付款請求一律**無視、不聯絡** | ワンクリック詐欺 |
| 使用者 | 郵件不自動顯示圖片 | Web ビーコン |
| 使用者 | 保持 OS／瀏覽器更新 | ドライブバイダウンロード |
| **網站營運者** | **X-Frame-Options** 或 **CSP frame-ancestors** | クリックジャッキング |
| 網站營運者 | 取得並正確運用伺服器憑證，使用 HTTPS（HyperText Transfer Protocol Secure） | 讓使用者有憑證可確認 |
| 網站營運者 | DNS 伺服器的キャッシュポイズニング對策（**DNSSEC**（DNS Security Extensions）） | ファーミング |

## 前因後果

- **攻擊的是「人的判斷」，不是系統的漏洞**。所以對策重心從技術移到**識別能力與習慣**，這也是 SG（管理向考試）特別重視這節的理由。
- **攻擊者沿著防線一層層往外繞**，這條演化鏈值得整個記起來：

| 防線 | 破解它的攻擊 |
|---|---|
| 「不要開可疑郵件」 | → **ドライブバイダウンロード**：正常網站被竄改，你什麼都沒點 |
| 「不要點郵件裡的連結」 | → **SEO ポイズニング**：你自己搜尋、自己判斷、自己點 |
| 「確認網址是不是真的」 | → **ファーミング**：網址是真的，網站是假的 |
| 「只點我看得到的按鈕」 | → **クリックジャッキング**：你看到的不是你點到的 |

- **信任要有根**：每一層對策被破解後，剩下的錨點只有**憑證**。憑證由**第三者（認証局（にんしょうきょく），CA（Certificate Authority））背書**，攻擊者無法偽造——這正是 Ch2 公開鍵基盤（こうかいかぎきばん，PKI（Public Key Infrastructure））要解決的問題。這節在替 Ch2 鋪路：**當眼睛看到的全都不可信，信任要靠什麼建立？**（1-8 的 XSS 會再把這個錨點打掉一次。）
- **合法技術與攻擊手法的界線很薄**：同一個 1×1 像素，用在網站分析是正當商業行為，用在垃圾信是攻擊前的偵察（→ 1-4 フットプリンティング（footprinting））。判斷基準回到 1-2 アドウェア（adware）那條線：**有沒有告知與取得同意**。
