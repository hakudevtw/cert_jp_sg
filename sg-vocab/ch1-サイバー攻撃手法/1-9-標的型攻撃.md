# 1-9 標的型攻撃

重要度：★★★

## 縮寫展開

| 縮寫 | 全名 | 日文 |
|---|---|---|
| **APT** | **Advanced Persistent Threat** | 持続的標的型攻撃 |
| **BEC** | **Business Email Compromise** | ビジネスメール詐欺 |
| **CSIRT** | **Computer Security Incident Response Team** | 事故應變專責團隊 |
| **J-CSIP** | **Initiative for Cyber Security Information sharing Partnership of Japan** | サイバー情報共有イニシアティブ |

## 標的型攻撃とは

針對**特定的對象或組織**的攻擊。事前會調查該組織的架構、人員、往來廠商、使用的系統，找出弱點後才動手。

### 迷惑メール vs 標的型攻撃メール

| | 迷惑メール（めいわくメール） | 標的型攻撃メール |
|---|---|---|
| 對象 | **不特定多數** | **特定組織** |
| 寄件人 | 不認識的人 | **看起來像組織內部成員或往來對象** |
| 內容 | 與自己無關 | **看起來可信、與自己的業務相關** |
| 偵測 | 大多可被過濾 | **幾乎偵測不到，通常很晚才發現** |

對照組：**ばらまき型（無差別亂灑）** ⇄ **標的型（特定對象）**。

### なぜ検出できないのか（三個理由，全是考點）

1. **亜種（あしゅ, variant）**——針對這個組織量身製作，全世界只有這一份，**パターンファイル 上不會有它的特徵碼**（→ 1-2）。防毒軟體不是失靈，是**根本沒看過**。偵測只能靠 **ビヘイビア法／サンドボックス**。
2. **送信數量極少**——垃圾信過濾靠「同一封信寄給幾百萬人」的統計特徵；標的型攻撃メール **只寄給 3 個人**，統計上完全不異常。
3. **內容與正常業務難以區分**——業務相關、組織公告、流感注意之類，本身不含任何惡意元素。

## 手法

### 標的型攻撃メール

冒用組織的郵件形式，寄送看似合理的信件：與業務相關的內容、組織公告、公開的提醒事項（流感、節日安排）。

### やり取り型攻撃（やりとりがたこうげき）

先寄**完全無害**的信（詢問報價、應徵履歷、業務諮詢），來回幾次，等承辦人員放下戒心，**才在某一封附上惡意檔案**。

**考點**：前幾封信裡**什麼惡意元素都沒有**，任何技術性檢查都會通過。等真正那封寄來時，收件人心理上已把對方當成「正在洽談的往來對象」。
**這是攻擊「人際信任的累積」，不是攻擊系統。**

### 水飲み場型攻撃（みずのみばがたこうげき, watering hole attack）

攻擊者不寄信，而是**竄改「標的組織的人一定會去看」的網站**（業界團體、常用新聞站、供應商網站），埋好 **ドライブバイダウンロード**，然後**等對方自己上門**。

名字來自獅子不追羚羊，而是守在水坑邊等牠來喝水。

**機制的精髓（常被誤解）**：被竄改的網站會**檢查來訪者的 IP 位址**，**只有當來訪者屬於標的組織的 IP 範圍時才送出攻擊程式碼**；其他所有訪客收到的是完全正常的網頁。

因此：
- 網站管理者自己測試 → **看起來一切正常**
- 資安研究者去看 → **什麼都找不到**
- 只有標的組織的人打開 → 中招

**「很難被發現」的真正原因不是隱藏得好，是攻擊只對特定對象顯現。**

與 1-7 的 **SEO ポイズニング** 同一個邏輯：繞過「不要點郵件裡的連結」那條防線，讓被害者在**自己主動、毫無可疑之處**的正常業務行為中中招。

### APT（持続的標的型攻撃）

**縮寫的三個字母就是定義本身**——過去問的正解敘述幾乎逐字對應：

| 字母 | 全名 | 對應正解敘述 |
|---|---|---|
| **A** | **Advanced**（高度） | 「**複数の攻撃方法を組み合わせ**」「防御策**に応じて**」——會看你怎麼防、然後換招 |
| **P** | **Persistent**（持続的） | 「**気づかれないように**」——不急著撈一票，長期潛伏 |
| **T** | **Threat**（脅威） | 見下 |

> **T 是「脅威（threat）」，不是「攻撃（attack）」。**
> APT 原本指的**不是一種攻擊手法，而是「執拗地盯上你的那個攻撃者集団」本身**——描述**主體**的詞，後來才泛稱這種攻擊型態。
> 所以題目敘述會從「**攻撃者が**特定の目的を持ち」開始——**主詞是人，不是技術。**

**記法：A＝換招、P＝不急、T＝是「誰」不是「什麼」。**

長期潛伏、持續竊取情報，由**多種攻擊手法組合**而成。惡意程式本身是**零件化組裝**的：

| 部分 | 內容 | 為什麼這樣分 |
|---|---|---|
| **共通攻撃部（きょうつうこうげきぶ）** | 任何標的都用得上的**通用部分**：侵入、建立據點、C&C 通信、権限昇格 | **重複使用**，省開發成本 |
| **個別攻撃部（こべつこうげきぶ）** | 針對**這個組織**量身打造：找特定檔案伺服器、認得該公司的業務系統、知道機密放哪 | **只有這次用**，所以沒有任何特徵碼 |

**考點**：共通攻撃部 因被重複使用，**有機會被既有對策偵測到**；個別攻撃部 是全新的，**偵測不到**。這解釋了 APT 為何能潛伏數月——**真正做壞事的那塊，防毒軟體從沒見過**。

（這又是 1-1「攻擊產業化＝分工」那條線：連惡意程式本身都模組化了。）

### BEC（ビジネスメール詐欺）

偽裝成經營層（「社長からの緊急指示」）或往來廠商（「振込先口座が変更になりました」），誘導承辦人員把錢匯到攻擊者帳戶。

**決定性特徵，也是它獨立成一個名詞的理由：**

> **BEC 通常不使用任何惡意程式。**

沒有附件、沒有連結、沒有 script——就是一封**純文字的正常郵件**。所以**防毒軟體、沙箱、IDS 全部無效**，因為技術上它根本不是攻擊。

**對策只能是業務流程層面的：**

| 對策 | 說明 |
|---|---|
| **別経路での確認（out-of-band）** | 收到變更匯款帳戶的指示時，**打電話**用**原本就知道的號碼**確認——不要用信裡寫的號碼 |
| 送金手續的**複数人チェック** | 一個人不能單獨完成匯款 |
| 電子署名 | 驗證寄件人身分 |

**「別経路確認」與 1-5 MITB 的 トランザクション署名 是同一個原理**：**當眼前的通道本身不可信時，答案永遠是「換一條路確認」。**

## 対策

### ① 組織面（SG 最愛考這層）

| 對策 | 重點 |
|---|---|
| **報告窗口明確化** | 每個人都知道「收到可疑信要通報誰」 |
| **CSIRT 的設置** | 專責的事故應變團隊 |
| **標的型攻撃メール訓練** | 故意寄模擬攻擊信給員工，測開啟率 |
| **確認是否有其他人也收到** | 多人同時收到類似的信＝這不是偶然，是針對性試探。也用於掌握被害範圍 |
| **不責備開了信的人** | ← 最容易被忽略但最關鍵 |
| **組織內外的資訊共享** | **J-CSIP**（IPA 主導，讓企業間共享攻擊情報） |

**「不責備」為什麼是對策**：標的型攻撃 的致命傷不是「有人點了」，而是「**點了的人不敢講**」。潛伏期越長損害越大，所以組織要營造「**開了就趕快說，不會被罵**」的文化。若通報等於挨罵，員工就會隱瞞，那幾個月就送給攻擊者了。

**這是典型的 SG 式答案——管理與文化的對策，不是技術對策。** 選項若出現「開啟可疑郵件者應予懲處」，八成是錯的。

### ② 技術面（入口／出口／內部三段）

| 段 | 對策 |
|---|---|
| **入口対策** | サンドボックス（未知檔案先在隔離環境跑）、附件類型限制、メールフィルタ |
| **出口対策** ← **本命** | 監控**對外的異常通信**（C&C 連線）、プロキシ 日誌監視、大量資料外送偵測 |
| **内部対策** | 網路分段（セグメント分割）、権限最小化、偵測橫向移動 |

**為什麼出口是本命**：標的型攻撃 **在入口擋不住**（亜種沒有特徵碼、寄送量太少、やり取り型前幾封完全無害）。既然一定會被突破，重心只能放在「進來之後怎麼早點發現」。

與 1-4 **サイバーキルチェーン** 的結論完全一致：**第 5～7 階段（インストール／遠隔操作／目的の実行）才是現實的偵測點。**

## 前因後果

**這一節是 Ch1 的收束點——前面每一種手法都在這裡被組合起來使用。**

標的型攻撃 不是一種新手法，而是**把 1-1 到 1-8 的東西按順序串成一條攻擊鏈**：
フットプリンティング（1-4）調查 → やり取り型／水飲み場型 取得入口 → ドライブバイダウンロード／マルウェア（1-2）感染 → 権限昇格・ルートキット（1-2）潛伏 → C&C 遠隔操作（1-2）→ 情報を圧縮・暗号化して持ち出す（1-4 キルチェーン 第 7 階段）。

**所以它的對策也不能是單點的**，必須是**多層防御**。

**三個「技術對策無效」的攻擊，構成這節的骨架：**

| 攻擊 | 為什麼技術擋不住 | 所以對策是什麼 |
|---|---|---|
| **やり取り型** | 前幾封信毫無惡意元素 | 人的警覺 ＋ 通報文化 |
| **水飲み場型** | 只對標的組織顯現惡意 | 出口対策、早期発見 |
| **BEC** | **根本沒有惡意程式** | **業務流程**（別経路確認、複数人チェック） |

**這正是 SG 與純技術考試的分界**：當攻擊瞄準的是「人的信任」與「業務流程的漏洞」時，答案不在防火牆裡，而在組織的規則與文化裡。
