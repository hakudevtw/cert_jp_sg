# 1-3 パスワードクラック

重要度：★★☆

## 攻撃手法

| 日文用語 | 讀音 | 英文 | 中文解釋 | 常考重點／易混淆點 |
|---|---|---|---|---|
| パスワードクラック | — | password cracking | 破解密碼的總稱 | — |
| 類推攻撃 | るいすいこうげき | guessing attack | 用使用者 ID、姓名、生日、地名、學校等個人資訊推測密碼 | 對策是「不要用有意義的字串」 |
| 辞書攻撃 | じしょこうげき | dictionary attack | 拿常用字典（password、123456、qwerty、admin…）逐一試 | **通常在 ブルートフォース 之前先跑一次**，因為 CP 值高 |
| ブルートフォース攻撃 | — | brute force attack | 又稱 **総当たり攻撃（そうあたりこうげき）**。針對**單一帳號**窮舉所有密碼組合 | 會觸發 **ロックアウト**，這是它的致命弱點 |
| リバースブルートフォース攻撃 | — | reverse brute force attack | 反過來：**固定一個密碼**，去試大量不同帳號 | **躲開 ロックアウト**（每個帳號只失敗一次）。方向相反是唯一判別點 |
| パスワードスプレー攻撃 | — | password spray attack | リバースブルートフォース 的進化版：同樣是一個密碼試多帳號，但**分散 IP、拉長時間間隔** | 目的是躲過「短時間內大量失敗」的偵測規則 |
| パスワードリスト攻撃 | — | password list attack | 用**其他網站外洩**的帳密組合，去登入別的服務 | **與系統本身的脆弱性無關**——你的系統再安全也擋不住。成因是使用者「密碼重複使用（使い回し）」 |
| クレデンシャルスタッフィング | — | credential stuffing（stuff＝押し込む，塞進去） | 與上者同原理，但**用工具大量自動化反覆嘗試** | 差別在**規模與自動化程度**，不在原理 |
| レインボーテーブル攻撃 | — | rainbow table attack | 用**預先算好**的「ハッシュ値 → 原始密碼」對照表反查 | 見下方專節，你原本的理解要修正 |
| ロックアウト | — | account lockout | 連續失敗 N 次就鎖住帳號 | 是 ブルートフォース 的對策，但擋不住 リバース／スプレー |

## ハッシュ値（ハッシュち）

密碼**不會以原文保存**，資料庫裡存的是經過 **ハッシュ関数（hash function）** 計算出的 **ハッシュ値（hash value）**。

三個性質（Ch2 會正式展開）：

| 性質 | 說明 |
|---|---|
| **一方向性（いっぽうこうせい）** | 由原文算 hash 很容易，由 hash 反推原文**在計算上不可行** |
| **固定長** | 不管輸入多長，輸出長度固定 |
| **衝突困難性** | 不同輸入算出相同 hash 極難（碰撞＝衝突, collision） |

**所以レインボーテーブル攻撃 在做什麼？**
既然不能反推，攻擊者就**改用查表**：事先把大量密碼算好 hash，做成對照表；拿到外洩的 hash 就直接查。純粹的全表太大，所以實際用「還原函數」把表壓縮，用**計算時間換儲存空間（time-memory tradeoff）**——這才是 rainbow table 的本質。

**不是「從 hash 找出規律」**——hash 沒有規律可找，那正是一方向性的意義。是「**事先算好、直接查**」。

**對策（必考）：**

| 對策 | 原理 |
|---|---|
| **ソルト（salt）** | 每個使用者加一段不同的隨機值再做 hash → 同樣的密碼算出不同 hash，**預先算好的表整個失效** |
| **ストレッチング（stretching）** | 反覆做 hash 幾千～幾萬次 → 拉長單次計算時間，讓窮舉與建表成本暴增 |

## 對策

| 攻擊 | 對策 |
|---|---|
| 類推攻撃 | 不要用有意義的單字、個人資訊 |
| 辞書攻撃 | 不要用字典裡的字 |
| ブルートフォース | **增加使用字元種類**（大小寫＋數字＋符號）＋**增加長度**。長度的效果大於複雜度 |
| ブルートフォース | **ロックアウト**（連續失敗就鎖） |
| リバース／スプレー | ロックアウト 無效 → 靠**異常登入偵測**（同一密碼多帳號、分散 IP 的失敗模式） |
| パスワードリスト／クレデンシャルスタッフィング | **不要在多個服務用同一組密碼**。組織側只能靠 **多要素認証（MFA）** |
| レインボーテーブル | **ソルト＋ストレッチング** |
| 全部 | **多要素認証（たようそにんしょう, MFA）**——密碼被破了也擋得住，是最強的單一對策 |

**現代觀念的轉向（愛出的陷阱題）**：**「パスワードの定期的な変更」現在已不被推薦。** 因為強制定期變更會讓使用者改成規律性的弱密碼（Password01 → Password02）。現行建議是「**不定期變更，但外洩時立即變更**」＋「長且唯一」＋MFA。選項若寫「定期的にパスワードを変更させる」要警覺。

## 前因後果

**攻擊方向翻轉，是為了繞過對策，不是為了更有效率。**
ブルートフォース 的天敵是 ロックアウト。所以攻擊者把方向轉 90 度：**リバースブルートフォース** 固定密碼、換帳號，於是每個帳號都只失敗一次，永遠碰不到鎖定門檻。**パスワードスプレー** 再加上分散 IP 與時間間隔，連「短時間大量失敗」的偵測規則也躲掉。三者是**同一條演化鏈**，題目考的就是你能不能看出「誰固定、誰變動」。

**パスワードリスト攻撃 是最難防的，因為破口不在系統而在使用者。**
它不利用任何脆弱性——帳號密碼都是「正確的」，系統沒有理由拒絕。這也是為什麼近年的正解一律往 **多要素認証** 走：既然「知道密碼」這件事已不可信，就得再加一個「持有物」或「生體情報」的因素。這條線 Ch2 認証 會正式展開。

**ハッシュ 的一方向性是防禦，レインボーテーブル 是繞過而非破解。**
攻擊者不去反推 hash（做不到），而是**事先把答案都算好**。ソルト 的巧妙之處在於：它讓「事先」這件事失去意義——每個人的鹽不同，表就得為每個人重算一次，攻擊經濟學直接崩潰。

## 待補（考後）

- ハッシュ関数 的具體演算法（MD5／SHA-1／SHA-256）與各自的安全狀態 → Ch2 補齊後回填
- 多要素認証 的三要素分類 → Ch2
- パスワードレス認証（FIDO2／パスキー）的現況
- 各攻擊在實際過去問中的出題頻率
