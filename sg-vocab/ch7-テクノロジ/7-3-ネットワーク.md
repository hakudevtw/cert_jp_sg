## ① 安全協定：TLS vs IPsec

**プロトコル**＝通訊雙方事先講好的約定。**セキュアプロトコル**的目的：加密（防竊聽）、認證（防冒充）、偵測竄改。

關鍵是**誰來加密**：

```
     應用程式（瀏覽器、郵件軟體）
  ┌──────────────────────────┐
  │ TLS：應用程式自己要求這條連線加密 │ 第 4 層
  ├──────────────────────────┤
  │ IPsec：OS／路由器把所有封包都加密 │ 第 3 層
  └──────────────────────────┘
```

| | TLS | IPsec |
|---|---|---|
| 層 | トランスポート層（第 4） | ネットワーク層（第 3） |
| 誰決定加密 | 應用程式自己 | OS 或路由器，應用程式不知道 |
| 保護範圍 | **一條連線** | **兩點之間的所有通訊** |
| 應用程式要配合 | 要支援 TLS | 不用，舊系統也自動受保護 |
| 設定 | **只有伺服器**要裝憑證，使用者不用做事 → 簡單 | **兩端都要設定** → 麻煩 |
| 普及 | 非常普及（HTTPS） | 主要用在**據點間 VPN** |

> 比喻：TLS＝每封信各自裝保險信封（寄件人自己封）；IPsec＝兩據點之間改用運鈔車，車上所有信都受保護，辦公室的人不用知道。
> **判斷**：保護某一個服務的連線 → TLS；保護兩個網路間的全部通訊，或應用程式無法自己加密（例：不能改程式的舊系統）→ IPsec。
> SSL 是 TLS 的前身，常寫成 SSL/TLS。**SSL-VPN**＝用 TLS 做的 VPN，只要瀏覽器就能連。

## ② Web・Mail 協定

| 協定 | 用途 | Port |
|---|---|---|
| HTTP | Web | **80** |
| HTTPS | 加密的 Web | **443** |
| SMTP | **寄信** | **25**（郵件伺服器之間）／**587**（使用者交給自己的伺服器，需認證） |
| POP3 | 收信，**下載到裝置** | **110** |
| IMAP4 | 收信，**留在伺服器** | **143** |

| | POP3 | IMAP4 |
|---|---|---|
| 信存哪 | 下載到裝置 | 伺服器 |
| 已讀狀態 | 存在下載那台，換裝置全部未讀 | 存在伺服器，**多台同步** |
| 適合 | 只用一台 | 手機、電腦多台 |

> POP＝郵局，把信領回家郵局就不管了；IMAP＝信留在郵局信箱，從哪看都同一個。
> **POP3、IMAP4 都只能收信**，寄信只有 SMTP。常考組合：寄 SMTP＋收（多台）IMAP4。

## ③ 其他協定

| 協定 | 用途 | Port | 資安角度 |
|---|---|---|---|
| TELNET | 遠端操作 | **23** | 明文，帳密會被竊聽（IoT 攻擊入口） |
| SSH | 安全的遠端操作 | **22** | 加密，取代 Telnet |
| FTP | 傳檔案 | **21** | 明文，改用 SFTP／FTPS |
| DHCP | 開機自動分配 IP | — | 假 DHCP 伺服器可把人導向假閘道 |
| DNS | 名稱（FQDN）→ IP | — | DNS 快取中毒、放大攻擊（1-6） |
| NTP | 正確時刻 | — | **各設備 log 時間一致**，事故調查才能對照 |
| SNMP | 遠端監控、控制網路設備 | — | 預設社群名稱沒改會被讀取設定 |
| RADIUS | 認證外部連入的使用者、設備 | — | IEEE 802.1X 背後的認證伺服器（5-6）；検疫ネットワーク |

**FQDN**：例如 `https://www.example.co.jp/index.html` 中的 `www.example.co.jp`。

### IP 四兄弟（第一天上班）

| 步驟 | 協定 | 做什麼 |
|---|---|---|
| 1. 櫃台發座位號碼 | **DHCP** | 分配 IP 給自己 |
| 2. 查通訊錄找王先生的座位號 | **DNS** | 名稱 → IP（**要通訊先問對方 IP**，最常考） |
| 3. 走到座位區確認是哪個人 | **ARP** | IP → MAC |

### Port 背法

```
21 FTP    F ┐
22 SSH    S ├ 字母順序＝號碼順序；SSH 是 Telnet 的安全版，住隔壁
23 Telnet T ┘
25 SMTP     寄信
587         寄件伺服器：5(我) 8(發) 7(出去)
110 POP3    日本報警電話 110：去郵局領信
143 IMAP4   1(I) 4(Love) 3(You)：每台裝置都同步
80 / 443    HTTP / HTTPS
```

POP3 比較舊 → 版本 3、port 110（都小）；IMAP4 比較新 → 版本 4、port 143（都大）。

**⚠ 錯過（10/4 背誦）**：寄件伺服器 port 寫成 413，正確是 **587**。

## ④ OSI・連接裝置・網路指令

分層的理由：各層各管各的，**換掉某一層不影響其他層**（有線換 Wi-Fi，瀏覽器不用改）。

### 寄國際包裹

| 層 | 名稱 | 比喻 | 例子 | 裝置 |
|---|---|---|---|---|
| 7 | アプリケーション | 決定寄什麼、用哪個服務 | HTTP、SMTP | ゲートウェイ（4〜7） |
| 6 | プレゼンテーション | 整理成對方看得懂的格式、加密、壓縮 | 編碼、加密 | ↑ |
| 5 | セッション | 約好開始和結束（電話的「喂」到「掰掰」） | 連線管理 | ↑ |
| 4 | トランスポート | **掛號**：保證送到、遺失重寄、排好順序 | TCP、TLS | ↑ |
| 3 | ネットワーク | **規劃路線**：台北經哪裡到東京 | IP、IPsec | **ルータ** |
| 2 | データリンク | 同一區內**站到隔壁站** | MAC | **ブリッジ、スイッチングハブ** |
| 1 | 物理 | 道路和卡車本身 | 網路線、電訊號 | **リピータハブ** |

> 口訣（7→1）：**All People Seem To Need Data Processing**（日本考生：アプセトネデブ）
> **2 層管隔壁、3 層管路線、4 層管送達。**
> **陷阱**：「確保送到」是第 4 層，不是第 3 層。第 2 層也有錯誤偵測、重傳，但只到隔壁站；第 4 層是端點到端點。

### 考題日文關鍵字 → 層

| 關鍵字 | 層 |
|---|---|
| 利用者に最も近い（最接近使用者） | 7 |
| エンドシステム間、ルーティング、中継 | 3 |
| 隣接ノード間の伝送制御、誤り検出 | 2 |
| 物理的な通信媒体、電気信号 | 1 |

### 連接裝置：越上層越聰明

| 裝置 | 層 | 根據 | 比喻 |
|---|---|---|---|
| リピータハブ | 1 | 不看任何東西，放大電訊號，送給**所有** port | 擴音器 |
| スイッチングハブ（L2） | 2 | 學習 **MAC**，只送給**目的地** port | 大樓收發室 |
| ルータ（L3） | 3 | 看 **IP**，選最佳路徑送到**別的網路** | 郵局 |
| ゲートウェイ | 4〜7 | **協定不同**的網路間轉換 | 翻譯 |

> 最常考：リピータ全部送 vs スイッチ只送目的地；スイッチ看 MAC（2）vs ルータ看 IP（3）。

### 網路指令

| 指令 | 做什麼 |
|---|---|
| ping | 確認能否**到達**對方 |
| ipconfig | 顯示、設定自己的**網路設定**（Windows；macOS 是 ifconfig） |
| arp | 顯示、設定 **IP ↔ MAC 對照表** |

## 前因後果

- **整節的資安主線：明文 → 加密**。Telnet→SSH、FTP→SFTP、HTTP→HTTPS，都是同一件事：舊協定設計時沒考慮竊聽。
- **加密要放在哪一層，決定了保護範圍與設定成本**（TLS vs IPsec），又是一次取捨。
- **很多協定本身就是攻擊面**：DNS（快取中毒）、DHCP（假伺服器）、SNMP（預設社群名稱）、Telnet（明文帳密）。
- **NTP 是事故調查的地基**：Ch4 的ログ管理、Ch8 的事件應變都假設 log 時間是一致的。
- **跟 Ch5 的接點**：防火牆看 IP 和 port（第 3〜4 層）、WAF 看 HTTP 內容（第 7 層）、IEEE 802.1X 用 RADIUS。理解 OSI 才知道每個產品在「看」什麼。

# Ch7 のまとめ

| 節 | 一句話 |
|---|---|
| 7-1 | 系統怎麼不停：處理形態 → 備援（デュアル／デュプレックス）→ RAID → 耐障害設計 → 用 RASIS、MTBF、MTTR、稼働率衡量 |
| 7-2 | 資料怎麼不壞：交易全有或全無 → 當機用日誌復原 → 同時修改用排他制御 → 被改壞用備份 → 資料分析用語 |
| 7-3 | 網路怎麼安全：協定從明文到加密、TLS vs IPsec、各協定的攻擊面、OSI 與裝置 |

**貫穿全章：**
1. **可用性與成本永遠在取捨**：デュアル vs デュプレックス、ホット vs コールド、RAID1 vs RAID5、ロック粒度、備份方式、TLS vs IPsec。
2. **備援 ≠ 備份**：RAID 和ホットスタンバイ會把錯誤同步過去；只有備份能回到「被改壞之前」。
