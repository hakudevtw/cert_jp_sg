## 本節的位置

5-2〜5-5 都在處理「公司邊界上的一道關卡」。本節處理邊界之外和之內的兩個問題：**分散在各地的人和據點，怎麼安全地連進來**（VPN）；**已經在內網裡的機器，怎麼再切開**（VLAN，回應 5-2 的內部對策）。兩者名字像，做的事剛好相反。
① VPN 與三種線路 → ② 兩條獨立的分類軸 → ③ 前提知識：網路分層與機器（Ch7 先修） → ④ VLAN → ⑤ 無線 LAN 上的 VLAN 與 802.1X 認證。

## ① VPN：在公眾網路上造一條專線

### 為什麼需要

網際網路是**公衆回線（こうしゅうかいせん）**，通信通常不加密，**很容易被盜聴（とうちょう）**（→ 1-4 スニッフィング（sniffing））。
VPN（Virtual Private Network）把通信**整個加密**，第三者無法竊聽；**同時包含認證技術**，所以也防なりすまし（→ 1-5）。

> **開 VPN 變慢，主因通常不是加密，是「繞路」。**
> 加解密現在很快；真正的成本是流量要先跑到 VPN 伺服器再出去。**連冰島的節點，封包就真的跑去冰島。**

### 三種線路

| | **専用線（せんようせん）** | **IP-VPN** | **インターネット VPN** |
|---|---|---|---|
| 實體 | **完全獨佔的一條線** | **電信業者的閉域網（へいいきもう），多家共用** | **公衆回線** |
| 隔離方式 | 物理上就分開 | **邏輯上分開** | **靠加密** |
| 費用 | **最貴** | 中 | **最便宜** |
| 品質 | 最穩 | 穩 | **不穩定** |
| 典型用途 | — | **企業據點之間** | 到處都能用 |

**IP-VPN 的定位是「用共用的基礎設施，做出接近專用線的效果」**：不必為每個客戶拉實體線，所以便宜；又不走公開網際網路，品質仍可控。

> **記法：専用線＝自己的路；IP-VPN＝公司內部的專用車道；インターネット VPN＝在公路上開一台有色玻璃的車。**

## ② ⚠️ 兩條互相獨立的軸（最常混淆）

**軸①：走在什麼線路上** → 就是上面那張表（インターネット VPN／IP-VPN）
**軸②：誰連到誰**

| | 內容 |
|---|---|
| **拠点間接続（きょてんかんせつぞく，LAN 間接続）** | 東京分公司 ←→ 大阪分公司，**網路對網路** |
| **リモートアクセス（remote access）** | **個人的一台電腦** → 公司內網 |

**兩條軸可以自由組合。** 常見誤解是把「FortiClient 這種遠端連線軟體」「NordVPN 這種消費者服務」拿來跟 IP-VPN 比——**前兩者屬於軸②，IP-VPN 屬於軸①。**

| 例 | 屬於 |
|---|---|
| 消費者 VPN 服務 | 機制上是**インターネット VPN**，目的是隱藏來源、繞地區限制 |
| 企業的遠端連線用戶端 | **リモートアクセス VPN**（軸②），底下通常跑インターネット VPN |
| **IP-VPN** | **只能在有拉線的據點之間用**——不可能「從任何地方連」 |

### リモートアクセス為什麼不穩

**前提就是「人在任何地方」**——家裡、咖啡廳、飯店、手機網路。**不可能在每間咖啡廳拉閉域線路**，只能走公衆回線。不穩的來源由近到遠：

| 來源 | 說明 |
|---|---|
| **自己這端的最後一哩** | 家裡 Wi-Fi、行動網路——**通常是最弱的一環** |
| **公衆回線** | 沒有人保證頻寬 |
| **VPN 閘道本身** | **全公司的人擠進同一個入口** |

> **VPN 閘道是集中點，集中點同時是效能瓶頸和 SPOF（Single Point Of Failure，單點故障）。**
> **這也是ゼロトラスト（zero trust）被推動的理由之一——不再把所有人繞進同一個入口。**

## ③ 前提知識：網路的「層」與各種機器

> **這段屬於 Ch7 テクノロジ系（→ 7-3），先寫在這裡，讀到 Ch7 時再整合。** 要理解 VLAN 在切什麼，必須先知道交換器看得到什麼。

### OSI 参照モデル（さんしょうモデル）

網路通信是**分層**的，每一層只管自己的事，剩下的交給下一層。

```mermaid
flowchart TB
    L7["第7層 アプリケーション層<br/>HTTP・SMTP・DNS<br/>「這個請求的意思是什麼」"]
    L4["第4層 トランスポート層<br/>TCP・UDP／ポート番号<br/>「送給這台機器的哪個服務」"]
    L3["第3層 ネットワーク層<br/>IP／IP アドレス<br/>「送到哪一台機器」"]
    L2["第2層 データリンク層<br/>MAC アドレス<br/>「同一個 LAN 內，下一個交給誰」"]
    L1["第1層 物理層<br/>電気信号・ケーブル"]
    L7 --> L4 --> L3 --> L2 --> L1
```

（第 5・6 層在 SG 幾乎不考。）

### 各機器「看得到第幾層」

| 機器 | 看到第幾層 | 依什麼決定去向 |
|---|---|---|
| **リピータハブ** | **第 1 層** | **不判斷**，收到訊號就全部複製出去 |
| **スイッチングハブ（L2 スイッチ）** | **第 2 層** | **MAC アドレス** |
| **ルータ／L3 スイッチ** | **第 3 層** | **IP アドレス** |
| **防火牆**（→ 5-2） | **第 3〜4 層** | IP 位址＋**埠號** |
| **IDS／IPS**（→ 5-4） | 第 3〜7 層 | ヘッダ＋內容 |
| **WAF**（→ 5-5） | **第 7 層** | **HTTP 請求的語意** |

> **Ch5 整章的產品差異，本質上就是這張表——「看得到第幾層」。**
> **層越高看得越細，但要拆的東西越多，所以越慢。** 這就是 5-5「看得越細、越慢越貴」的真正原因。

### MAC アドレス vs IP アドレス

| | **MAC アドレス** | **IP アドレス** |
|---|---|---|
| 綁在哪 | **網卡本身**，出廠固定 | **邏輯上指派**，換地方就變 |
| 有效範圍 | **只在同一個 LAN 內** | **跨網路都有效** |
| 角色 | **下一站交給誰** | **最終目的地的地址** |

**寄包裹的比喻剛好貼切**：IP アドレス是包裹上的**收件地址**，全程不變；MAC アドレス是**每一段運送中下一個經手的人**——每段都不同，**但地址從頭到尾是同一個。**
**所以スイッチングハブ（第 2 層）只能在同一個 LAN 內送，跨網路必須交給ルータ（第 3 層）。**

### リピータハブ vs スイッチングハブ

| | **リピータハブ（ハブ）** | **スイッチングハブ（L2 スイッチ）** |
|---|---|---|
| 收到訊框 | **往所有埠複製一份** | **只送到目的地那個埠** |
| 怎麼知道送哪 | 不知道 | **學習每個埠後面掛著哪些 MAC アドレス** |
| 後果 | **所有人都看得到別人的通信** | 其他埠**看不到** |

> **這正是 1-4 スニッフィング的背景**：在老式ハブ上竊聽是免費的；
> **在スイッチングハブ上，攻擊者必須另外做 ARP スプーフィング（ARP spoofing）去騙交換器**，門檻高很多。

## ④ VLAN：把一台交換器切成好幾台

### 為什麼需要

**就算用了スイッチングハブ，同一台交換器上的所有埠仍屬於同一個ブロードキャストドメイン（broadcast domain）**——ARP（Address Resolution Protocol）這類廣播訊框還是送給全部人。**在網路的意義上，它們是同一個網路。**

> **VLAN（Virtual LAN）＝把連在スイッチングハブ上的機器分組管理的功能：讓一台實體交換器在邏輯上變成好幾台互相獨立的交換器。**

**VLAN 之前：只能買兩台**

```mermaid
flowchart LR
    SW1["スイッチA<br/>業務用"] --- P1["PC ×3"]
    SW2["スイッチB<br/>機密用"] --- P3["PC ×3"]
```

兩台交換器、兩套線路、彼此沒有任何電線相連——靠的是「**物理上根本沒接起來**」。

**VLAN 之後：一台就夠**

```mermaid
flowchart LR
    SW["スイッチングハブ 1台"]
    SW ---|"ポート 1-3<br/>VLAN 10（業務）"| A["PC ×3"]
    SW ---|"ポート 4-6<br/>VLAN 20（機密）"| B["PC ×3"]
```

**交換器設定成「1–3 號埠和 4–6 號埠互相看不見」**，效果等同兩台獨立交換器。

省下的不只是機器錢：

| 省掉什麼 |
|---|
| 第二台交換器的購置與維護 |
| **第二套實體線路的佈線工程** |
| 機房空間、電力 |
| **人員調部門時重新拉線** → 改設定就好 |

最後一項實務上最有感：以前員工調部門要請人去機房拔線改插，**有 VLAN 之後改個設定即可。**

### 分組方式

| 方式 | 怎麼分 |
|---|---|
| **ポート VLAN** | 依**實體埠號**分組（1–3 號業務、4–6 號機密）。**最主要的方式** |
| **タグ VLAN（IEEE 802.1Q）** | 在訊框裡**加 VLAN ID 標籤**，讓**同一條線承載多個 VLAN** → **可跨多台交換器** |

**承載多個 VLAN 的埠叫トランクポート（trunk port）。**

### ⚠️ VLAN 之間不能直接通信

> **跨 VLAN 必須經過ルータ或 L3 スイッチ。**

**這對資安很有價值**——跨區流量全被迫經過一個點，**可以在那裡做存取控制**。**這就是 5-2 說的内部対策**：攻擊者就算打下一台業務用 PC，**也無法直接橫向移動到機密網段。**

## ⑤ 無線 LAN 上的 VLAN 與 IEEE 802.1X

### 一台 AP，多個 SSID

**一台アクセスポイント（AP）可以同時發出多個 SSID（Service Set Identifier），每個 SSID 對應一個 VLAN ID。**

```mermaid
flowchart LR
    SW["スイッチングハブ"] ---|"トランクポート<br/>タグVLAN で両方を1本に"| AP["アクセスポイント（1台）"]
    AP ---|"SSID: Corp → VLAN 10"| V10["業務ネットワーク"]
    AP ---|"SSID: Guest → VLAN 20"| V20["ゲスト用<br/>インターネットのみ"]
```

**注意 AP 到交換器只有一條線。** 兩個 VLAN 的流量都走那條，**靠訊框上的 VLAN 標籤區分**——這就是タグ VLAN 的實際用途。最常見的應用是**訪客 Wi-Fi**：訪客能上網，**但碰不到公司內部任何東西。**

### 動的 VLAN（どうてき VLAN，ダイナミック VLAN）

**同一個 SSID 也能分流**：使用者連上時先認證，**認證伺服器（RADIUS）依「你是誰」決定把你丟到哪個 VLAN。**這套連線前認證的標準就是 **IEEE 802.1X**。

> **同一個 SSID、同一支手機——業務部的人進業務網段，訪客進訪客網段。**

### 認證方式的強弱

| 方式 | 怎麼驗 | 強度 |
|---|---|---|
| **MAC アドレス認証** | 只看網卡號碼 | **最弱**——MAC 可偽造 |
| **ID／密碼**（EAP-PEAP 等） | 帳密送到認證伺服器比對 | 中 |
| **クライアント証明書（client certificate）**（EAP-TLS） | **裝置裡預先安裝一張數位憑證** | **最強** |

**クライアント証明書的內容就是 2-6 的 PKI（Public Key Infrastructure）**：公司自架**認証局（にんしょうきょく，CA）**，發憑證給每台配發的電腦（內含**該裝置的公開鍵（こうかいかぎ）＋CA 的署名（しょめい）**），裝置自己保管**秘密鍵（ひみつかぎ）**。

> **連線時裝置用秘密鍵簽名，證明「這張憑證是我的」——跟 2-6 的伺服器憑證同一套機制，只是方向反過來：這次是客戶端向伺服器證明自己。**

**放進 2-9 的框架：這是所有物認証（しょゆうぶつにんしょう，something you have）**——「擁有那把秘密鍵」就是持有物。**再加上使用者輸入的帳密，就構成多要素認証（たようそにんしょう）。**

**憑證靠 MDM（Mobile Device Management）統一派送**——所以公司配發的筆電能自動連上內網 Wi-Fi，自己的手機不行。

## 前因後果

- **VPN 和 VLAN 名字很像，做的事剛好相反**——本節最該記住的對比：

| | **VPN** | **VLAN** |
|---|---|---|
| 目的 | **把分散的東西連起來** | **把連著的東西分開** |
| 手段 | **加密**（在公開線路上造私密通道） | **標籤／埠號**（在同一台交換器上造邊界） |
| 解決的問題 | 距離 | **信任的混雜** |
| 對應的對策層 | 主要是**入口対策**（安全地進來） | **内部対策**（進來了也去不了別處） |

- **兩者都是 virtual：「物理上不是那樣，但邏輯上當作那樣」。** VPN 物理上走公眾網路，邏輯上當作專線；VLAN 物理上是一台交換器，邏輯上當作好幾台。**這個思路本身就是 Ch5 的主旋律：不改實體，改規則。**
- **DMZ 和 VLAN 在做同一件事——把「信任」切成區塊**：DMZ 用防火牆切「公開／內部」（→ 5-3），VLAN 用交換器切「部門／機密等級」。**而 802.1X 的動的 VLAN 把它推到極致：信任等級不由「你插在哪個埠」決定，而由「你是誰」決定**（信任要有根：根在 CA 簽發的憑證）。

> **這條線的終點就是ゼロトラスト——連「位置」都不再給任何信任（→ 5-8）。**

- **與其他節的連結**：

| 相關 | 連結 |
|---|---|
| **1-4 スニッフィング** | VPN 的加密直接消滅它；スイッチングハブ提高了它的門檻 |
| **1-5 なりすまし** | VPN 內含的認證技術對應它 |
| **1-9 標的型攻撃** | **VLAN 的網路分離是限制橫向移動的主力** |
| **2-6 PKI** | クライアント証明書＝PKI 在企業內網的實作 |
| **2-9 認証の三要素** | 802.1X 的憑證認證＝**所有物認証** |
| **5-2 三層対策** | VLAN 是典型的**内部対策** |
| **5-3 DMZ** | **同一個思想的不同尺度** |
| **5-7 無線 LAN** | エンタープライズモード＝802.1X；リピータハブ的「媒體共用」結構再現 |
