## ① 偵測方式：從「認身分」到「看行為」

### 為什麼需要不只一種

最直覺的做法是記住每隻病毒長什麼樣，見到就擋。但 1-2 的ポリモーフィック型（polymorphic）每次感染都換外觀，1-10 的ゼロデイ攻撃（zero-day attack）根本沒人見過——於是偵測方式一路演化。

| 方式 | 原理 | 弱點 |
|---|---|---|
| **パターンマッチング法** | 與**定義済み（ていぎずみ）的シグネチャ**比對 | **對未定義（未知）的惡意程式無效** |
| **静的ヒューリスティック法** | **不執行**，只分析程式碼內容 | 程式碼被**難読化（なんどくか）**就分析不了 |
| **ビヘイビア法**（＝**動的ヒューリスティック法**） | 把**受檢程式本身**丟進**サンドボックス實際執行**，觀察行為 | 病毒在サンドボックス內**刻意不作惡**就抓不到（サンドボックス検知回避） |
| **チェックサム法**（＝**インテグリティチェック法**） | 事前記錄檔案的ハッシュ値／チェックサム，**比對是否變化** | **必須在確定乾淨時記錄**（見下） |

判定時當作「可疑行為」的例子：檔案的**寫入・複製・刪除**、**通信量異常**、竄改登錄檔（registry）等。

### 静的 vs 動的

> **静的（せいてき）＝不執行，只讀程式碼。**
> **動的（どうてき，＝ビヘイビア法）＝實際讓它跑，看它做了什麼。**

heuristic 這個字在這裡發揮作用：判斷依據不是「**有沒有見過這隻**」，而是「**這種寫法／動作很像惡意程式**」。**所以它能對付未知的惡意程式**——這是與パターンマッチング法的決定性差異。

### ⚠️ チェックサム法的致命前提

> **記錄的當下必須是乾淨的。**
> 若在**已經感染的狀態**下記錄基準值，之後永遠比對不出異常。

**自編例**：伺服器上線第一天記錄所有系統檔的雜湊值 → 三個月後某檔雜湊值變了 → 有人動過它。但如果上線那天就已中毒，基準值本身就是「中毒版」，之後再怎麼比都一致。

## ② 隔離：不判斷，讓它碰不到你

### 為什麼需要

① 的所有方式都在做「判定」，而判定一定會被反制：ビヘイビア法一出來，攻擊方就做出察覺自己在虛擬環境就乖乖不動的病毒。於是出現另一條路：**不再判斷善惡，直接假設全部有害，讓它在隔離環境裡跑。**

| 技術 | 內容 |
|---|---|
| **サンドボックス** | 隔離的虛擬環境。**名字本身就是比喻——在沙坑裡怎麼弄髒都影響不到外面** |
| **ウェブアイソレーション** | 網頁在**隔離環境（伺服器端）**開啟，**只把「畫面」傳到手邊** |

### ウェブアイソレーション 的要點

**網頁的程式碼從頭到尾沒有進到使用者的 PC**，手邊看到的只是畫面影像。惡意腳本在隔離環境裡執行，**用完整個丟棄**。

> **與其判斷它有沒有害 → 不如讓它根本碰不到你。**
> **這與パターンマッチング那種「先判定再擋」是完全不同的思路，稱為無害化（むがいか）。**

## ③ 使用者端的對策

產品再好，使用者端的習慣沒做對一樣會出事。

| 對策 | 重點 |
|---|---|
| **定義ファイル（ていぎファイル）保持最新** | 別名很多：**パターンファイル／ウイルス定義ファイル／シグネチャファイル**——全是同一個東西。**善用自動更新** |
| **外部或網路取得的檔案一定要檢查** | 特別是**実行形式（じっこうけいしき）ファイル**：`.exe` `.pif` `.com` `.bat` `.scr` |
| **設定成顯示拡張子（かくちょうし）** | → 下方「二重拡張子」 |
| **善用應用程式的資安功能** | 例：對付**マクロウイルス（macro virus）**，**停用 Office 巨集** |
| **套用修正パッチ（しゅうせいパッチ）** | 補 OS、瀏覽器的漏洞 |
| **資料備份** | 惡意程式造成的破壞**常常無法復原** |

### ⚠️ 二重拡張子（にじゅうかくちょうし）

Windows **預設隱藏**已知的副檔名，所以 `請求書.pdf.exe` 會**顯示成 `請求書.pdf`**。再把圖示**偽装（ぎそう）成 PDF 圖示**，外觀上完全分不出來。

> **這就是「要顯示副檔名」這條對策的理由。**
> 也是 1-7 標的型攻撃メール的固定手法。

### ⚠️ 備份的陷阱

備份用的磁碟如果**一直連著**，會**連同備份一起被ランサムウェア（ransomware）加密**。

> **光是「有備份」不夠。必須離線保管，才算對策。**（答案的延伸 → 5-8 WORM）

## ④ 觀測裝置：ハニーポット 與 ダークネット

前三段都在「保護某台機器」。這兩個不保護任何人，**是情報收集裝置**——要知道現在外面流行什麼攻擊，才知道該優先防什麼。

| | **ハニーポット** | **ダークネット** |
|---|---|---|
| 做法 | **放誘餌、會回應**，引攻擊者進來互動 | **什麼都不放、不回應**，只看誰送東西過來 |
| 看得到 | **攻擊手法的細節**（進來後做了什麼） | **大範圍的活動趨勢**（全世界現在在流行什麼） |
| 性質 | 能動的（のうどうてき） | 受動的（じゅどうてき） |

### ダークネット 為什麼成立

**未使用的 IP 位址空間＝那裡沒有任何人**，所以**不可能有正常通信送到那裡**。

> **抵達ダークネット的封包，100% 都是不正常的。**
> 掃描、ワーム（worm）的感染活動、DDoS 的反彈流量（バックスキャッタ）等等。
> **不需要任何判斷善惡的邏輯——抵達本身就是證據。**

日本由 **NICTER** 負責這類觀測。

## 前因後果

- **本節是 Ch1 的正面回答，回答順序跟著攻擊演化走：**

| Ch1 的問題 | 本節的答案 |
|---|---|
| 1-2 マルウェア的存在 | パターンマッチング法 |
| 1-2 ポリモーフィック型（每次換長相） | **シグネチャ失效 → ヒューリスティック法** |
| 1-10 ゼロデイ攻撃（未修補、未知） | **ビヘイビア法**（沒見過也能從行為判斷） |
| 1-2 ファイルレスマルウェア（檔案不落地） | **ビヘイビア法**（沒有檔案可比對，只能看行為） |
| 1-7 標的型攻撃メール的附件 | **サンドボックス**裡先開、**顯示副檔名** |
| 1-2 ランサムウェア | **離線備份** |

- **偵測的主線：「認識這隻病毒」→「這東西看起來像病毒」→「這東西做的事像病毒」。** 判斷依據從「身分」移到「行為」，因為攻擊方先讓「身分」每次都不同——**長相可以偽造，但要達成目的就必須做出那些動作。**
- **攻擊方再反擊（サンドボックス検知回避（けんちかいひ）），防守方就讓前提不成立**：ウェブアイソレーション不再判斷善惡，直接假設全部有害。這是 Ch2「與其把秘密藏好，不如讓秘密不需要送出去」在產品層的版本——**與其判斷它是不是惡意的，不如讓它根本碰不到你。** 同形狀之後還會在 5-8 VDI 出現。
- **ハニーポット／ダークネット是另一層的東西**：對應 1-1 的結論——攻擊已經產業化，防守也必須情報化。
- **往後接**：「判定一定能被反制」這個限界，5-4 IDS／IPS 會以誤検知的形式再次出現。
