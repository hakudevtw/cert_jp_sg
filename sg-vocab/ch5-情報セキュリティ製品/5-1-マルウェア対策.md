# 5-1 マルウェア対策

重要度：★★☆

## 縮寫展開

| 縮寫／外來語 | 英文全名 | 日文／說明 |
|---|---|---|
| **パターンマッチング法** | pattern matching | 特徴（シグネチャ）照合 |
| **ヒューリスティック法** | **heuristic**（発見的・経験則にもとづく） | 静的／動的の二種 |
| **ビヘイビア法** | **behavior**（行動） | ＝動的ヒューリスティック法 |
| **チェックサム法** | checksum | ＝**インテグリティチェック法**（integrity check） |
| **サンドボックス** | **sandbox**（砂場） | 隔離実行環境 |
| **ハニーポット** | **honeypot**（蜜壺） | 囮システム |
| **ダークネット** | **darknet** | 未使用 IP アドレス空間 |
| **ウェブアイソレーション** | **web isolation** | ブラウザ分離 |

## マルウェア対策ソフトの検出方式

| 方式 | 讀音 | 原理 | 弱點 |
|---|---|---|---|
| **パターンマッチング法** | — | 與**定義済みのシグネチャ**比對 | **未定義（未知）のマルウェアには無力** |
| **ビヘイビア法**（**動的ヒューリスティック法**） | — | 把**檢查對象的程式本身**丟進 **サンドボックス 實際執行**，觀察行為 | 病毒在 サンドボックス 內**刻意不作惡**就抓不到（サンドボックス検知回避） |
| **静的ヒューリスティック法** | — | **不執行**，只分析程式碼內容 | **難読化（なんどくか）** されると解析できない |
| **チェックサム法**（**インテグリティチェック法**） | — | 事前記錄檔案的ハッシュ値／チェックサム，**比對是否變化** | **必須在確定乾淨的狀態下記錄**（見下） |

### 判定に使われる「不審な挙動」の例

ファイルの**書込み・複製・削除**、**通信量の異常**、レジストリの改変 など。

### ⚠️ チェックサム法の致命的な前提

> **記錄的當下必須是乾淨的。**
> 若在**已經感染的狀態**下記錄基準值，之後永遠比對不出異常。

### 軸：静的 と 動的

> **静的＝不執行，只讀程式碼。**
> **動的（＝ビヘイビア法）＝実際に走らせて、振る舞いを見る。**

**heuristic 這個字的意思在這裡發揮作用**：判斷依據不是「**有沒有見過這隻**」，而是「**這種寫法／動作很像惡意程式**」。
**所以它能對付未知的惡意程式**——這是它與 パターンマッチング法 的決定性差異。

## 観測・分析のしくみ

| | **ハニーポット** | **ダークネット** |
|---|---|---|
| 做法 | **放餌、會回應**，引攻擊者進來互動 | **什麼都不放、不回應**，只看誰送東西過來 |
| 看得到 | **攻撃手法の細部**（進來後做了什麼） | **大範囲の活動傾向**（現在全世界在流行什麼） |
| 性質 | 能動的 | 受動的 |

### ダークネット が成立する理由

**未使用の IP アドレス空間＝そこには誰もいない。**
したがって **正常な通信が届くはずがない**。

> **抵達 ダークネット 的封包，100% 都是不正常的。**
> 掃描、ワーム 的感染活動、DDoS 的反彈流量（バックスキャッタ）等等。
> **不需要任何判斷善惡的邏輯——抵達本身就是證據。**

日本では **NICTER** がこの観測を行っている。

## 隔離という考え方

| 技術 | 內容 |
|---|---|
| **サンドボックス** | 隔離された仮想環境。**名前が比喩そのもの——砂場の中でどれだけ汚しても外に影響しない** |
| **ウェブアイソレーション** | Web ページを**分離環境（サーバ側）で開き、「画面」だけを手元に転送する** |

### ウェブアイソレーション の要点

**網頁的程式碼從來沒有進入使用者的 PC**，手邊看到的只是畫面影像。
惡意腳本在隔離環境裡執行、**用完整個丟棄**。

> **判斷它有沒有害 → 讓它根本碰不到你。**
> **這與パターンマッチング 那種「先判定再擋」是完全不同的思路（＝無害化）。**

## 利用者側の対策

| 対策 | 重點 |
|---|---|
| **マルウェア定義ファイルを最新に** | 別名多：**パターンファイル／ウイルス定義ファイル／シグネチャファイル**——全是同一個東西。**自動更新を活用** |
| **外部・ネットから入手したファイルは必ず検査** | 特に**実行形式ファイル**：`.exe` `.pif` `.com` `.bat` `.scr` |
| **拡張子を表示する設定にする** | → 下記「二重拡張子」 |
| **アプリのセキュリティ機能を活用** | 例：**マクロウイルス**対策として Office の**マクロを無効化** |
| **修正パッチ（セキュリティパッチ）の適用** | OS・ブラウザの脆弱性を塞ぐ |
| **データのバックアップ** | マルウェアの破壊は**復元できないことが多い** |

### ⚠️ 二重拡張子（にじゅうかくしし）

Windows は既知の拡張子を**既定で隠す**ため、`請求書.pdf.exe` が **`請求書.pdf` と表示される**。
さらに **PDF のアイコンを偽装（アイコン偽装）** すれば、見た目では判別不能。

> **これが「拡張子を表示せよ」という対策の理由。**
> 1-7 標的型攻撃メール の定番手口。

### ⚠️ バックアップの罠

備份用的磁碟如果**一直連接著**，會**連同備份一起被 ランサムウェア 加密**。

> **光是「有備份」不夠。必須離線保管，才算是對策。**

## 前因後果

**本節是 Ch1 的正面回答，而且回答的順序完全跟著 Ch1 的攻擊演化走。**

| Ch1 的問題 | 本節的答案 |
|---|---|
| 1-2 マルウェア 的存在 | パターンマッチング法 |
| 1-2 ポリモーフィック型（每次換長相） | **シグネチャが効かない → ヒューリスティック法へ** |
| 1-10 ゼロデイ攻撃（パッチ前・未知） | **ビヘイビア法**（見たことがなくても振る舞いで判る） |
| 1-2 ファイルレスマルウェア（檔案不落地） | **ビヘイビア法**（比對不到檔案，只能看行為） |
| 1-7 標的型攻撃メールの添付 | **サンドボックス**で開いてみる、**拡張子表示** |
| 1-2 ランサムウェア | **オフラインバックアップ** |

**檢測方式的演化有一條清楚的主線：**

> **「認識這隻病毒」→「這東西看起來像病毒」→「這東西做的事像病毒」。**
> **判斷的依據從「身分」移到「行為」。**

理由是攻擊方先動的：**ポリモーフィック型 讓「身分」每次都不同**，於是防守方只好改看**行為**——因為**長相可以偽造，但要達成目的就必須做出那些動作**。

**但攻擊方又反擊了**：**サンドボックス 檢知回避**——病毒察覺自己在虛擬環境裡就乖乖不動。
於是防守方再進化到 **ウェブアイソレーション** 這種思路：**不再判斷善惡，直接假設全部有害**。

> **這就是 Ch2 那句話在製品層的版本：與其把秘密藏好，不如讓秘密不需要送出去。**
> **這裡則是：與其判斷它是不是惡意的，不如讓它根本碰不到你。**

**ハニーポット／ダークネット 則是另一個層級的東西**——它們不保護任何人，**是情報收集裝置**。
對應 1-1 的結論：**攻擊已經產業化，所以防守也必須情報化**。你要知道「現在外面在流行什麼」，才知道該優先防什麼。
