## 本節的位置

5-1 守的是「檔案與終端」。本節把視角拉到**網路的邊界**：外面的網際網路和公司內網之間，要有一道關卡決定誰能過。這是最直覺的防禦，也是 Ch5 整條產品線的起點——防火牆**為了速度而放棄看的東西**，就是 5-3 DMZ、5-4 IDS・IPS、5-5 WAF 各自存在的理由。
① 防火牆看什麼 → ② 規則怎麼寫 → ③ 它看不到什麼 → ④ 和ルータ（router）、パーソナルファイアウォール（personal firewall）的區別 → ⑤ 承認邊界會破之後的三層對策。

---

## ① 防火牆與パケットフィルタリング

設在**外部網路與公司內網的境界（きょうかい）**，**遮断（しゃだん）不正當的通信**。

**自編例**：規則「遮斷不經過プロキシサーバ（proxy server）的『內→外』通信」→ 其中一個目的是**切斷惡意程式與 C&C（Command and Control）伺服器的通信**（→ 1-2 ボットネット）。

### パケットフィルタリング（packet filtering）型只看ヘッダ

只拿**封包的ヘッダ（header）**比對規則，**不看內容（ペイロード，payload）**。判斷材料：

| 判斷材料 |
|---|
| **送信元（そうしんもと）／宛先（あてさき）IP 位址** |
| **送信元／宛先ポート番号（port number）** |
| **通信方向**（內→外／外→內） |
| **TCP（Transmission Control Protocol）旗標 SYN／ACK**——判斷是新連線還是既有連線的回應 |

> **只看ヘッダ，所以能高速處理大量通信——它是用「放棄看內容」換來速度的。**

## ② 規則設定：ホワイトリスト與順序

### ブラックリスト vs ホワイトリスト

| | **ブラックリスト方式** | **ホワイトリスト方式** |
|---|---|---|
| 清單上列的是 | **要拒絕的** | **要允許的** |
| 沒列到的 | **放行**（預設允許） | **拒絕**（**デフォルトディナイ**） |
| 強度 | **只防得了已知的威脅** | **未知的一律遮斷** |

> **防火牆的基本原則是ホワイトリスト方式——「原則禁止、例外許可」。**

和 5-1 對照：**ブラックリスト ≒ パターンマッチング法**（認得的才擋）；**ホワイトリスト ≒ ウェブアイソレーション**（沒許可的一律當有害）。

### ⚠️ 設定順序（考點）

1. **先**排允許必要通信的規則
2. **最後**放「全部拒絕」的規則

> **規則由上往下評估，第一條符合的就套用。**
> 所以全部拒絕**一定在最後一行**。放在第一行的話，**下面的允許規則永遠讀不到**，全部通信都停擺。

最後那一行叫 **暗黙の拒否（あんもくのきょひ，implicit deny）／デフォルトディナイ**——**也就是ホワイトリスト方式在實作上的樣子。**

**自編例**：
```
1. 允許 任意 → Web 伺服器 :443
2. 允許 內網 → Proxy :8080
3. 拒絕 全部        ← 必須在最後
```

## ③ 防火牆的限界

「只看ヘッダ」帶來三個看不到的東西：

| 限界 | 內容 | 補位的產品 |
|---|---|---|
| **判斷不了通信本身是否正當** | 形式正當的通信大量湧入＝**DoS（Denial of Service）攻擊**（→ 1-6）會直接通過 | **IDS／IPS**（→ 5-4） |
| **內容是攻擊也照放** | **スクリプト攻撃**（SQL インジェクション、XSS（Cross-Site Scripting） → 1-8）在形式上是正當通信 | **WAF**（→ 5-5） |
| **對內部犯行（ないぶはんこう）無力** | 從正規位置、正規埠號送出，分不出來 | → **ゼロトラスト**（→ 5-8） |

> **封包外形合法、內容是攻擊就會直接通過。SQL インジェクション、XSS 在防火牆眼中，只是一筆正常的 80 號埠 HTTP 通信。**
> **防火牆的世界觀是「內與外」，但威脅未必來自外面。**

## ④ 容易混的兩個：ルータ、パーソナルファイアウォール

### ルータ vs ファイアウォール

**ルータ**＝在**網路層（OSI 第 3 層）連接不同網路**的裝置，和防火牆一樣放在網路的邊界。

| | **ルータ** | **ファイアウォール** |
|---|---|---|
| **本業** | **転送（てんそう）**：把封包送到正確的網路 | **遮断**：擋掉不該通過的 |
| 對方的功能 | 也有簡易的**パケットフィルタリング** | 也能轉送 |
| 差別 | 過濾功能**簡單** | 規則細、有日誌、有狀態管理 |

課本描述ルータ時用「轉送是本業、功能**充実（じゅうじつ）**」——充実＝功能完備，轉送這件事做得特別齊全。

> **兩者都放在邊界、都具備對方的功能。判斷點是「主要目的是哪個」，不是「有沒有這個功能」。**

### 一般防火牆 vs パーソナルファイアウォール

| | **一般防火牆** | **パーソナルファイアウォール** |
|---|---|---|
| 形態 | 硬體／軟體 | **安裝在每台終端上的軟體** |
| 守的地方 | **組織的邊界** | **每台終端** |
| 目的 | 防止外部不正アクセス（ふせいアクセス） | **防止資訊外流、防止損害擴大** |

**定位是「內部對策」**——一般防火牆只守邊界，**內網一被突破就毫無防備**。每台終端各裝一個，等於**在內部也畫出邊界**。

## ⑤ 三層對策：承認「侵入は防げない」

### 為什麼出現

> **「侵入は防げない」（入侵擋不住）——只做入口對策不夠。**

這是 **1-9 標的型攻撃／APT（Advanced Persistent Threat）**逼出來的結論：對方會花好幾個月慢慢試，**入口遲早被突破**。於是防禦重心從「在門外擋住」移到「進來了也什麼都做不了、帶不出去」。

| | 目的 | 手段例 |
|---|---|---|
| **入口対策（いりぐちたいさく）** | **不讓進來** | 防火牆、郵件過濾、防毒軟體 |
| **内部対策（ないぶたいさく）** | 進來之後**不讓擴散、早點發現** | 日誌監視、權限最小化、網路分離、パーソナルファイアウォール |
| **出口対策（でぐちたいさく）** | **不讓東西出去** | 遮斷可疑的對外通信（**C&C 通信**、資料外帶） |

**自編例**：員工點開釣魚信附件中毒（入口被破）→ VLAN 讓它碰不到機密網段（內部）→ 它想連 C&C 伺服器回報，被「必須經 Proxy」的規則擋下（出口）。

## 前因後果

- **本節是「在邊界守」這個想法的到達點，同時也宣告了它的限界。** パケットフィルタリング用「放棄看內容」換速度，而**放棄的部分就是後續產品的存在理由**：

| 放棄的東西 | 撿起來的產品 |
|---|---|
| 內容（ペイロード） | **WAF**（應用層攻擊，→ 5-5） |
| 通信的「量」「模式」異常 | **IDS／IPS**（→ 5-4） |
| 加密通信的內容 | **SSL インスペクション**（→ 5-8 待補） |
| 「內與外」這個前提本身 | **ゼロトラスト**（→ 5-8） |

- **但在看這些之前，下一節 5-3 先處理一個更基本的問題**：有些伺服器必須讓外面連進來，那它要放在防火牆的哪一邊？
- **最後一列最大**：防火牆的世界觀建立在「內部可以信任」之上，而 1-9 標的型攻撃和內部犯行**直接打破這個前提**。入口→內部→出口的三層式（也就是多層防御（たそうぼうぎょ，defense in depth），→ 4-3），是從承認邊界會被突破開始的。
- **和 5-1 同一個形狀**：不是把判定做得更精密，而是把前提換掉。
