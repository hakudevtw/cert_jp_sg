# 5-2 ファイアウォール

重要度：★★☆

## 縮寫展開

| 用語 | 英文全名 | 說明 |
|---|---|---|
| **ファイアウォール** | **firewall**（防火牆） | FW と略される |
| **パケットフィルタリング** | packet filtering | ヘッダ情報でふるい分ける |
| **C&C サーバ** | **Command and Control**（＝**C2**） | マルウェアの司令塔（→ 1-2） |
| **WAF** | **Web Application Firewall** | → 5-3 以降 |
| **IDS／IPS** | **Intrusion Detection / Prevention System** | → 5-3 以降 |

## ファイアウォール

設置在**外部網路與公司內部網路的邊界**，**遮斷不正當的通信**。

例：**遮斷不經過 プロキシサーバ 的「內部→外部」通信**
→ 目的の一つは**マルウェアの C&C 通信を断つこと**（→ 1-2 ボットネット）。

### パケットフィルタリング型

只看**封包的 ヘッダ部 資訊**來比對規則。**不看內容（ペイロード）。**

**判斷材料：**

| 項目 |
|---|
| **送信元 IP アドレス／宛先 IP アドレス** |
| **送信元ポート番号／宛先ポート番号** |
| **通信の方向**（内部→外部／外部→内部） |
| **TCP のフラグ（SYN／ACK）**——判斷是新連線還是既有連線的回應 |

### ⚠️ 「中身を見ない」ことの帰結

> **封包長得合法、但內容是攻撃なら素通りする。**
> **SQL インジェクション、XSS（→ 1-8）在防火牆眼中，就只是一個正常的 80 番ポート HTTP 通信。**

**これが WAF が必要になる理由。**

## ルール設定

| | **ブラックリスト方式** | **ホワイトリスト方式** |
|---|---|---|
| 清單上列的是 | **拒否するもの** | **許可するもの** |
| 沒列到的 | **放行**（デフォルト許可） | **拒否**（**デフォルトディナイ**） |
| 強度 | **既知の脅威しか防げない** | **未知のものは一律遮断** |

> **防火牆的基本原則是 ホワイトリスト方式——「原則禁止、例外許可」。**

### 設定の順序（考點）

1. **先に**、必要な通信を**許可**するルールを並べる
2. **最後に**、すべてを**拒否**するルールを置く

> **ルールは上から順に評価され、最初に合致したものが適用される。**
> だから全拒否は**必ず最終行**。先頭に置くと**下の許可ルールが永遠に読まれず**、全通信が止まる。

最後那一行的規則叫做 **暗黙の拒否（implicit deny）／デフォルトディナイ**。
**＝ホワイトリスト方式 在實作上長的樣子。**

### 5-1 との対応

**ブラックリスト ≒ パターンマッチング法**（認得的才擋）
**ホワイトリスト ≒ ウェブアイソレーション**（沒許可的一律當有害）

## ファイアウォールの限界

| 限界 | 中身 | 補う製品 |
|---|---|---|
| **通信そのものの正当性は判断できない** | 正当な形の通信が大量に来る＝**DoS 攻撃**（→ 1-6）を素通りさせる | **IDS／IPS** |
| **内容が攻撃でも通す** | **スクリプト攻撃**（SQL インジェクション・XSS →1-8）は通信としては正当 | **WAF** |
| **内部犯行に無力** | 正規の位置から正規のポートで送られるため区別できない | → **ゼロトラスト**の発想へ |

> **防火牆的世界觀是「內與外」。但威脅未必來自外面。**

## ルータ と ファイアウォール

**ルータ**＝在**ネットワーク層（OSI 第 3 層）連接不同網路**的裝置。
和防火牆一樣放在**網路的邊界**。

| | **ルータ** | **ファイアウォール** |
|---|---|---|
| **本業** | **転送**（封包送到正確的網路） | **遮断**（擋掉不該通過的） |
| 對方的功能 | 簡易な**パケットフィルタリング**は持つ | 転送もできる |
| 差別 | 過濾機能は**簡素** | ルールが細かい・ログ・状態管理 |

**「本業が通信データの転送であり、その機能が充実している」**
＝**充実（じゅうじつ）＝功能完備**。轉送這件事做得特別齊全。

> **両者とも境界に置かれ、両者とも相手の機能を持つ。**
> **判斷點は「主な目的はどちらか」——機能の有無ではない。**

## パーソナルファイアウォール

| | **通常のファイアウォール** | **パーソナルファイアウォール** |
|---|---|---|
| 形態 | ハードウェア／ソフトウェア | **個々の端末にインストールするソフトウェア** |
| 守る場所 | **組織の境界** | **端末ごと** |
| 目的 | 外部からの不正侵入の防止 | **情報の流出防止・被害の拡大防止** |

**位置づけは「内部対策」**——従来の FW は境界しか守らないので、**内網に入られた時点で無防備**。端末ごとに置くことで**内部にも境界を引く**。

## 三つの対策レイヤ（重要）

| | 目的 | 手段例 |
|---|---|---|
| **入口対策（いりぐちたいさく）** | **入れない** | ファイアウォール、メールフィルタ、マルウェア対策ソフト |
| **内部対策** | 入られた後、**拡散させない・早く気づく** | ログ監視、権限最小化、ネットワーク分離、パーソナルファイアウォール |
| **出口対策（でぐちたいさく）** | **出さない** | 不審な外向き通信の遮断（**C&C 通信**、データ持ち出し） |

### この三分割が生まれた理由

> **「侵入は防げない」——入口対策だけでは足りない。**

這是 **1-9 標的型攻撃／APT** 逼出來的結論。對方會花好幾個月慢慢試，**入口遲早會被突破**。
**だから防御の重心が「門の外で止める」から「入られても何もさせない・持ち出させない」へ移った。**

## 前因後果

**本節は「境界で守る」という発想の到達点であり、同時にその限界の宣言でもある。**

ファイアウォール 是「劃分內外、在邊界設關卡」這種**最直覺的防禦**。
パケットフィルタリング **只看 ヘッダ**，因此能高速處理大量通信——**它是用「放棄看內容」換來速度的。**

**その諦めた部分が、そのまま後続製品の存在理由になる：**

| 諦めたもの | それを拾う製品 |
|---|---|
| 中身（ペイロード） | **WAF**（アプリケーション層の攻撃） |
| 通信の「量」「パターン」の異常 | **IDS／IPS** |
| 暗号化された通信の中身 | **SSL インスペクション**（→ 5 章後半） |
| 「内と外」という前提そのもの | **ゼロトラスト** |

**そして最後の行が一番大きい。**
FW の世界観は **「内側は信用できる」** という前提の上に建っている。
だが 1-9 の標的型攻撃も、内部犯行も、**その前提を直接崩す**。

> **入口対策 → 内部対策 → 出口対策 這個三段式，是從「承認邊界會被突破」開始的。**
> **和 5-1 看到的是同一個形狀：不是把判定做得更精密，而是把前提換掉。**
