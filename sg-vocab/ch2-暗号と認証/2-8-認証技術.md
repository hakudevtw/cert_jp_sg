# 2-8 認証技術

## 縮寫展開

| 縮寫 | 全名 | 日文／說明 |
|---|---|---|
| **MAC** | **Message Authentication Code** | メッセージ認証符号 |
| **HMAC** | **Hash-based Message Authentication Code** | 用 hash 函數實作的 MAC |
| **TSA** | **Time Stamping Authority** | 時刻認証局 |
| **PIN** | **Personal Identification Number** | 暗証番号 |

## 認証の三分類

| 種類 | 讀音 | 確認什麼 | 使用的技術 |
|---|---|---|---|
| **利用者認証**（ユーザ認証・本人認証） | りようしゃにんしょう | **是不是本人** | パスワード、**ワンタイムパスワード**、**PIN**、生体認証 等 |
| **メッセージ認証** | — | **訊息有沒有被竄改** | **メッセージ認証符号（MAC）**、**デジタル署名** |
| **時刻認証** | じこくにんしょう | **時刻有沒有被竄改**（例：日誌的記錄時間） | **タイムスタンプ** |

**三者確認的對象完全不同：人／訊息／時間。** 題目會混在一起問「以下技術屬於哪種認証」。

## メッセージ認証符号（MAC）

**用途**：確認通信內容是否被竄改。與 デジタル署名 功能相近，但**技術基礎與能力不同**。

| | **メッセージ認証符号（MAC）** | **デジタル署名** |
|---|---|---|
| 使用的技術 | **共通鍵暗号方式**（或 hash＋鍵＝**HMAC**） | **公開鍵暗号方式**（秘密鍵で署名、公開鍵で検証） |
| **完全性** | ✅ | ✅ |
| **認証** | ✅ | ✅ |
| **否認防止** | **❌ できない** | **✅ できる** |
| **処理速度** | **速い** | 遅い |

### ⚠️ なぜ MAC は否認防止ができないのか（最重要）

> **共通鍵是「雙方共有」的** → **收件人自己也做得出一模一樣的 MAC**
> → 寄件人可以主張「**那是你自己偽造的**」，第三者無法判斷是誰做的。

而 デジタル署名 使用的秘密鍵**只有本人持有**，收件人做不出來 → **賴不掉**。

**這是 2-2／2-3 那個「共通鍵 vs 公開鍵」差異的直接後果**：
**共有的東西無法證明歸屬，獨有的東西才能。**

## タイムスタンプ（時刻認証）

由**第三者機關「時刻認証局（TSA）」**發行的時刻為基準。

**比喻：郵便の消印（けしいん，郵戳）**——
**郵戳證明的不是信的內容，而是「這封信在那個時間點確實存在過」。**

### 証明する二つのこと

| 證明什麼 | 日文 |
|---|---|
| **那個時間點，這份文件確實存在** | **存在証明（そんざいしょうめい）** |
| **從那時起，內容沒有被改過** | **非改ざん証明** |

### なぜデジタル署名だけでは足りないのか

デジタル署名 證明「**誰**簽的」與「**沒被竄改**」，但**證明不了「什麼時候簽的」**。

**實務上時間為什麼重要：**

> 若簽署者的証明書後來失效了（→ 2-6 CRL／OCSP），
> **要怎麼判斷這份文件是失效前簽的、還是失效後偽造的？**
> **有 タイムスタンプ 就能證明「簽署發生在失效之前」，署名依然有效。**

### 組み合わせによる否認防止の厳密さ

| 組合 | 能證明什麼 |
|---|---|
| **兩者都沒有** | 什麼都證明不了 |
| **デジタル署名 のみ** | **誰**簽的、**沒被竄改** |
| **デジタル署名 ＋ タイムスタンプ** | **誰**、**在什麼時候**簽的、**之後沒被竄改** → **否認防止最嚴謹** |

## 前因後果

**本節把 Ch2 的技術按「認証的對象」重新整理了一次。**

Ch2 前半（2-1〜2-7）是按**技術**分類（共通鍵／公開鍵／hash／PKI），本節改用**目的**分類（認人／認訊息／認時間）。
**同一個技術會出現在不同分類裡**——デジタル署名 既是 メッセージ認証 的手段，也參與 時刻認証 的組合。**考題常從「目的」出發問「該用什麼」，所以兩種分類都要能互相轉換。**

### MAC 與 デジタル署名 的選擇，是速度與否認防止的取捨

| 場景 | 該用哪個 | 理由 |
|---|---|---|
| 高頻率的通信（每個封包都要驗） | **MAC** | 快。而且通信雙方本來就互相信任，不需要對第三者證明 |
| 契約、電子文書、法律效力 | **デジタル署名** | **需要否認防止**——事後要能對第三者證明「就是他簽的」 |

**這呼應了 2-4 ハイブリッド 的同一種智慧：不是選「最強的」，而是選「這個場景需要的」。**

### 三種認証各自補上了 Ch1 的洞

| Ch1 的問題 | 本節的對應 |
|---|---|
| 1-3 パスワードクラック → 密碼不夠安全 | **利用者認証** 的強化（ワンタイムパスワード、多要素認証 → 2-9） |
| 1-5 なりすまし・改ざん | **メッセージ認証** |
| 1-4 日誌可被竄改、攻擊痕跡被抹除（ルートキット） | **時刻認証**——日誌的時間戳若能被竄改，事後追查就失去依據 |

**最後一項值得特別記**：1-2 講 ルートキット 會竄改日誌來隱藏痕跡，1-4 講攻擊者會抹除紀錄。
**タイムスタンプ 正是對抗這件事的技術**——**讓「紀錄何時產生」本身也成為無法否認的事實。**
