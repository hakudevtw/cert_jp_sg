## 本節的位置

系統複雜到利害關係人（股東、顧客、往來廠商、銀行）看不懂是否可靠，所以請**獨立第三方**客觀評估，給出**保證（お墨付き）**或**建議（助言）**。像財報要會計師簽證。

## ① システム監査・情報セキュリティ監査

| | システム監査 | 情報セキュリティ監査 |
|---|---|---|
| 對象 | **資訊系統** | 組織的**全部資訊資產** |
| 看什麼 | 可靠性、安全性、效率性、有效性 | 資安管理的實施狀況 |
| 共同點 | 都是**第三者的評價** | |

### 經濟產業省的兩份基準（必考）

| 基準 | 給誰 | 內容 |
|---|---|---|
| **情報セキュリティ管理基準** | **被稽核的組織** | 組織應做的事（最佳實務）；稽核時是**判斷的尺度** |
| **情報セキュリティ監査基準** | **稽核員** | 稽核員的**行為規範**：獨立性、守秘義務等 |

> 比喻：管理基準＝評分標準（考生照它作答、閱卷拿它評分）；監査基準＝監考老師守則。
> 陷阱：「判斷尺度是監査基準」→ ❌。

**「尺度」＝量東西的尺，比對用的標準，不是方向。** 實際評量：稽核員從管理基準挑出適用項目 → 逐條對照、蒐集證據 → 未做到的寫成指摘事項。
例：管理基準要求「離職時立即停用帳號」→ 拿人事部離職名單比對系統帳號清單，離職三個月仍能登入就是缺失。

### 稽核員的兩條規則

1. **必須獨立**：自己部門稽核自己 ❌（球員兼裁判）。
2. **可以找其他專家協助**：不熟的領域可請專家支援。

## ② 保證型 vs 建議型、稽核 vs 顧問

| | 保証型監査 | 助言型監査 |
|---|---|---|
| 目的 | 向外部證明措施適當 | 給組織改善建議 |
| 給誰看 | 利害關係人 | 組織內部 |
| 例子 | 雲端服務商每年受稽核並公開結果給客戶 | 剛起步的公司請稽核員指出不足 |

| 考點 | 正確 | 誘答 |
|---|---|---|
| 誰決定哪一型 | **監査依頼者**依需求決定 | 稽核員決定 |
| 兩者關係 | **不互斥**，可**先助言型改善、再保證型證明** | 互斥；先保證再助言 |
| 處理大量利害關係人資料的系統 | 定期保證型並公開結果 | — |

| | 監査 | コンサルティング |
|---|---|---|
| 共同點 | 都給委託方建議 | |
| 報告給誰 | 稽核對象＋**利害關係人** | **只給委託組織** |
| 目的 | 取得利害關係人的信任 | 掌握自己的狀況 |

> 稽核是給「別人」看的證明；顧問是給「自己」看的健檢。

## ③ 内部統制・IT統制

**「統制」＝英文 control**（internal control），不是中文「管制」的意思。指為確保目標達成而建立的機制，包含三步：

| 步驟 | 意思 | 餐廳洗手規定 |
|---|---|---|
| 整備 | 訂規則 | 進廚房前要洗手 |
| 実施 | 照著做 | 員工每次都洗 |
| **証明** | **留證據** | 洗手打卡紀錄 |

重點在**證明**：稽核員看的就是這些證據。日本上市公司依金融商品取引法（J-SOX）須評估並報告內部統制。目的不是限制人，而是讓錯誤與舞弊不易發生、發生也找得到，並能證明。

**内部統制**：防止財務會計的錯誤與舞弊。例：付款從申請到匯款同一人處理 → 易挪用 → 申請與核准分開（**職務分掌**）。

**IT統制**：內部統制中與 IT 相關的部分。

| 依時機 | 做法 | 例子 |
|---|---|---|
| 予防統制 | 事前讓錯誤不易發生 | 單筆匯款超過 100 萬無法送出；只給必要權限；畫面設計防輸錯 |
| 発見統制 | 事後找出錯誤 | 比對系統訂單筆數與紙本張數；比對合計金額與原始單據 |

> 與 Ch4「防止 vs 檢知」同概念。

| 依對象 | 管什麼 | 例子 |
|---|---|---|
| IT業務処理統制 | 用系統做的**每項業務本身** | 價格只能從主檔選取；超過上限不處理 |
| IT全般統制 | 讓業務處理統制能正確運作的**整體環境**（開發、運用、權限） | 程式修改須測試與核准才能上線；定期檢查存取權限 |

> 全般統制＝地基，業務処理統制＝房子。系統本身有錯（bug 刪除財務資料、權限不當導致外洩），內部統制就不完整。

**プルーフリスト**：把輸入資料印出與原始單據逐一比對，找漏輸、重複（例：50 張訂單系統只有 49 筆）。典型的發現統制。

## ④ 三種ガバナンス

ガバナンス＝治理，強調**組織自己的決策與監督機制**（不同於 government 的由上管下）。

| 治理 | 一句話 | 例子 |
|---|---|---|
| コーポレートガバナンス | 利害關係人**監督經營者**的機制 | 獨立董事 |
| ITガバナンス | 依經營策略適當運用 IT，管控員工 IT 使用 | 決定三年內核心系統上雲 |
| 情報セキュリティガバナンス | 把資安意識與措施貫徹到組織，管理資訊資產風險 | 經營層訂資安方針、定期聽取稽核報告 |

### 範圍（必考）

| | ITガバナンス | 情報セキュリティガバナンス |
|---|---|---|
| IT 且資安（多因素認證） | ✅ | ✅ |
| 資安非 IT（紙本機密文件鎖保險櫃、門禁） | ❌ | ✅ |
| IT 非資安（導入 ERP 提升效率） | ✅ | ❌ |

> **部分重疊，但誰都不包含誰；兩者都在企業治理之內。**
> 陷阱：「互相獨立不重疊」❌、「資安治理被 IT 治理包含」❌、反之亦 ❌。

## 前因後果

- **信任需要第三方**：利害關係人看不懂系統，就靠獨立稽核員的保證。這跟 Ch2 PKI「信任要有根」是同一個邏輯：憑證靠 CA、系統靠稽核員。
- **管理基準是 ISMS（Ch3）的延伸**：組織照它做、稽核員拿它量。
- **統制的核心是「能證明」**：Ch4 的ログ管理、Ch7 的 NTP 時刻同步、8-2 的變更管理紀錄，都是留下證據的手段。
- **予防／発見 = Ch4 防止／檢知**；**職務分掌**對應 Ch4 的最小權限與權限分離。
- **治理是最上層**：決定方向（ガバナンス）→ 建立機制（統制）→ 檢查（監査）。這三層由上而下串起整章。
