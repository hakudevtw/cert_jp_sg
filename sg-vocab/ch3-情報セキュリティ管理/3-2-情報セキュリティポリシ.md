## 三層構造

**基於 ISMS 訂定的政策文件，分為三層。**

| 層 | 日文 | 英文 | 回答什麼 | 公開？ | 誰負責 | 類比 | 修訂頻率 |
|---|---|---|---|---|---|---|---|
| **① 基本方針** | 情報セキュリティ基本方針 | **ポリシー（policy）** | **Why** | **公開** | **情報セキュリティ委員会** | **憲法** | 幾乎不改 |
| **② 対策基準** | 情報セキュリティ対策基準 | **スタンダード（standard）** | **What** | **非公開** | **情報セキュリティ委員会** | **法律** | 數年一次 |
| **③ 実施手順** | 情報セキュリティ実施手順 | **プロシージャ（procedure）** | **How** | **非公開** | **各情報システムごと・各部門ごと** | **省令（施行細則）** | 幾乎每年 |

### 公開／非公開 的理由

| | 為什麼 |
|---|---|
| **基本方針は公開** | 它是**對外的理念宣言**，目的就是**取得外部信賴** |
| **対策基準・実施手順は非公開** | **寫的是實際的防守方式，公開等於把防禦配置交給攻擊者** |

### 「憲法 → 法律 → 省令」這個類比很貼切

> **越上層越抽象、越穩定；越下層越具體、越常改。**

### ⚠️ 「情報セキュリティポリシ」有兩種用法（考點）

> **廣義＝三層全部；狹義＝只指上面兩層（基本方針＋対策基準）。**
> **狹義的用法更常見。**

理由與「誰負責」直接相關：

| | 誰訂 | 適用範圍 |
|---|---|---|
| **基本方針・対策基準** | **情報セキュリティ委員会（全社）** | **全公司統一** |
| **実施手順** | **各情報システムごと・各部門ごと** | **每個系統／部門不同** |

**前兩層是「全公司共通的規範」，第三層是「各自的操作手冊」——性質不同，因此常被排除在「ポリシ」之外。**
（每個部門用的系統不一樣，寫不出一份共通的操作手冊。）

## ① 情報セキュリティ基本方針

**闡述（説く，とく）為什麼組織必須投入資安的宣言文。** 由社會背景、法令等觀點說明基本理念。
**組織內部關於資安的「憲法」，不會頻繁修訂。**

### 應記載的項目

| 項目 | 內容 | 例 |
|---|---|---|
| **基本理念・目的** | 表明組織對資安的態度 | 「組織が情報セキュリティに取り組む姿勢を表明する」「全ての従業者が守るべき包括的な基準として、情報セキュリティポリシを策定する」 |
| **役割・位置付け** | ポリシ 在文書體系中的地位 | 「情報セキュリティポリシは、情報セキュリティ対策文書の最高位に位置し、全ての従業者の指針となる」 |
| **見直し・改訂** | 定期檢視的宣告 | 「情報セキュリティポリシの見直しを定期的に行い、将来に渡り維持する」 |
| **適用対象範囲** | 明確規範適用對象 | 會社作成的文書、外部取得的情報、個人情報也包含。**従業者包含経営層、正社員、派遣社員、アルバイト** |
| **評価** | 自我稽核或第三方檢核的宣告 | — |
| **罰則** | 違反者的明確處分 | 「違反した場合、就業規則、契約書に従って処分の対象となることがある」 |

### ⚠️ 兩個容易被考的細節

**① 適用範圍裡的「従業者」包含 派遣社員・アルバイト。**
→ 不是只有正職。**外部人員、委外廠商也常被納入。**

**② 罰則必須連結到「就業規則」。**
→ **沒有寫在就業規則裡，法律上就無法處分。** 呼應 3-1「罰則要明確記載在就業規則」。

**另外**：基本方針**必須經過經營層核准並對外宣示**——那就是 3-1 說的**経営陣のコミットメント**的具體形式。

## ② 情報セキュリティ対策基準

**依基本方針制定的明確規則・規程。又稱「管理策」。**
例：事故發生時的處理方式、文書管理規程 等。

### ⚠️ ベースラインアプローチ

**不可能從頭自己想出所有對策。** 通常是從**管理策集**或**ひな形（ひながた，範本）**出發，再依組織實況修改。
**這個做法叫 ベースラインアプローチ（baseline approach）。**

> **baseline ＝ 基準線。先拉一條現成的標準線，再依自己狀況調整，而不是從零開始。**

**常見的 ひな形 來源：**

| 來源 | 內容 |
|---|---|
| **JIS Q 27002** | **管理策の実践規範**——最標準的那本 |
| **IPA「中小企業の情報セキュリティ対策ガイドライン」** | 附錄有**規程のサンプル**，可直接改用 |
| **JNSA** 的政策範本 | 民間團體提供的樣本 |

> **預告：ベースラインアプローチ 是「リスク分析手法」的其中一種，3-3 會跟另外三種一起出現。**

### 具體的基準例

| 規格 | 內容 |
|---|---|
| **JIS Q 27002** | 日本國內産業規格，由 **ISO/IEC 27002 翻譯**而來 |
| **JIS Q 27017** | **クラウドサービス固有**的管理策規格。建立在 27002 之上，規範 **cloud service customer（利用者）與 cloud service provider（提供者）之間** |
| **JIS Q 27018** | **雲端上的個人情報保護** |

### 對象別的基準

| 對象 | 制定者 |
|---|---|
| **政府機関向け** | **サイバーセキュリティ戦略本部**（設於内閣）制定，適用省庁等政府機関 |
| **地方公共団体向け** | **総務省**制定的資安 guideline |

**サイバーセキュリティ戦略本部 的事務局叫 NISC（内閣サイバーセキュリティセンター）**——**這個縮寫考試會直接出現。**

## ③ 情報セキュリティ実施手順

**依対策基準制定的具體運用手冊（マニュアル文書）。**

**例**：使用者 ID 與 password 的運用手冊、マルウェア 對應手冊、backup 手冊、外部委託契約手續 等。

**與対策基準同樣，通常從 ひな形 出發再依實況改寫——也就是套用 ベースラインアプローチ。**

## 情報セキュリティポリシ のポイント

| | 檢查什麼 |
|---|---|
| **①** | **全社をカバー**しており、**自組織の状況に合った**内容か |
| **②** | **経営層が承認**し、**予算や人の配分は適切**か |
| **③** | **順守（じゅんしゅ）すべき法令を網羅**しているか |

**這三點各自對應一個典型的失敗模式：**

| 檢查點 | 防止的失敗 |
|---|---|
| ① 全社 ＋ 合身 | **抄範本抄到底**，寫了一堆跟自己無關的東西，或漏掉自己特有的風險 |
| ② 経営層の承認 ＋ 資源配分 | **只有文件沒有預算**，寫得再好也執行不了 |
| ③ 法令の網羅 | **違法而不自知** |

**②特別值得記**：呼應 3-1 的 **トップダウン**——**「経営層が承認した」不只是形式，它同時意味著預算和人力被配置下來。沒有資源的政策等於沒有政策。**

## 前因後果

**3-1 說 ISMS 是「機制」，3-2 就是那個機制的骨架——把抽象的理念一路翻譯成可執行的動作。**

**三層結構解決的是一個很現實的矛盾：**

> **理念必須穩定，否則失去權威；操作必須善變，否則跟不上技術。**
> **如果只寫一份文件，這兩個要求會直接打架。**

**所以拆成三層，讓「改動頻率」與「抽象程度」對齊：**

| | 抽象度 | 改動頻率 | 改動成本 |
|---|---|---|---|
| **基本方針** | 高 | 極低 | 高（要經營層重新核准、對外重新宣示） |
| **対策基準** | 中 | 數年 | 中 |
| **実施手順** | **低（具體到操作）** | **幾乎每年** | **低（部門自己改）** |

**下層可以頻繁修改而不動搖上層——這正是分層的意義。**
換了新的防毒軟體、改用新的雲端服務，**只要改実施手順就好，基本方針一個字都不用動。**

### 與其他節的連結

| 相關 | 連結 |
|---|---|
| **3-1 経営陣のコミットメント** | **基本方針的核准與對外宣示**就是它的具體形式 |
| **3-1 罰則を就業規則に明記** | 基本方針的「罰則」項目 |
| **3-1 PDCA** | 「見直し・改訂」項目＝ Check→Act 被寫進了文件本身 |
| **3-3 リスク分析** | **ベースラインアプローチ** 會在那裡重新出現 |
| **Ch6 法規** | 「順守すべき法令を網羅しているか」直接指向那一章 |

**最後一個觀察**：基本方針要公開、對策基準與実施手順不公開——
**這個切法本身就是一個資安判斷。**

> **對外要展示「我們有在做」，但不能展示「我們怎麼做」。**
> **前者建立信賴，後者洩漏防禦配置。**

**這跟 5-8 那題「LAN アナライザ 的保管場所不可周知」是同一個原則的不同尺度**——
**資安措施的「存在」可以公開，「細節」不行。**
